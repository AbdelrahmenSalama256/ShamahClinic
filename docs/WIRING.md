# WIRING — what the site shows, and where each byte comes from

Generated by the audit on 2026-10-12. Every visible text block and image on every route, in both
languages, with the WordPress evidence for the verdict.

> **Transport has changed since this audit (BK-7.3, 2026-10-22).** The `WP` column and the endpoint
> shorthand below still describe *where the content originally came from*, but nothing is read from
> WordPress at build or request time any more: `src/lib/wp/http.ts` is deleted, each reader returns
> from the committed `data/wp/*.json` snapshot, and a kind moves to MariaDB as soon as the console
> publishes one row of it. `scripts/sync-wp.mjs` is the only code left that reaches the origin, by hand.
> The gate table in §19 (including its "snapshot fallback" row) is a record of the run that day.

> **The shell has changed too (BK-14.2, 2026-10-28).** The rows below that call the menu, the branch
> strip, the booking label or the clinic name STATIC now name a file that is only a fallback: the
> console's `nav` and `branches` rows answer for the first two, the Texts screen addresses the third,
> and `getBrandWords()` reads the fourth from Settings. `bookCta` is gone from `src/data/nav.ts`.

Columns, as the brief asks:

| column | meaning |
|---|---|
| **element** | what renders, with its `file:line` |
| **source now** | `WP` = read from WordPress at request time (live REST, `data/wp/*.json` snapshot at build), `STATIC` = an authored file under `src/data`, `CONFIG` = `src/config/site.ts` |
| **WordPress source?** | `no`, or `yes` plus the exact endpoint / page or product id / HTML selector that proves it |
| **action** | what the audit did: `wired`, `kept WP`, `kept STATIC (reason)`, `removed`, `dead` |

Rules the verdicts follow (from the brief, unchanged): WordPress is read with **GET only**; nothing
is written to it; nothing is hidden, merged, filtered or rewritten — a dashboard value is displayed
exactly as returned, even when it is theme demo text or an English auto-excerpt under an Arabic
title; only content with no WordPress source stays authored, and every such item is listed here and
in `docs/inventory.md`.

Evidence key (endpoints used throughout):

| shorthand | endpoint |
|---|---|
| `PAGES` | `GET {restBase(lang)}/wp/v2/pages?per_page=100` — 27 rows EN, 27 rows AR |
| `PAGE(slug)` | `GET {restBase(lang)}/wp/v2/pages?slug=…` |
| `POSTS` | `GET {restBase(lang)}/wp/v2/posts?per_page=100` — 92 rows |

| `SETTINGS` | `GET /wp/v2/settings` — title, tagline, URLs only; no phone, email, hours or address |
| 622 / 696 / 32 / 67 / 169 / 3 / 9 / 62 / 837 / 885 | page ids, `PAGE_IDS` in `src/lib/wp/config.ts:50-58` |

Language note: the AR subsite is TranslatePress. Its page **titles** are real Arabic (622 الرئيسية,
32 معلومات عنا, 696 خدماتنا, 9 العروض, 62 معلومات طبية, 67 اتصل بنا, 169 أهم الأسئلة الشائعة,
885 حقن البوتوكس) while page **bodies** are frequently the untranslated English. Every Arabic field
therefore goes through `arabicRatio(...) > 0.3` (`src/lib/wp/lang.ts:6-11`) before it replaces the
authored Arabic; the fallbacks are listed in §17.
